# バンド物販レジ

iPhoneのSafariからホーム画面へ追加して使える、バンド内専用のオフライン物販会計PWAです。商品・会計履歴・設定は端末内のIndexedDBに保存され、サーバー送信やログインはありません。

## 主な機能

- 商品登録、編集、非表示、削除
- ドラッグ＆ドロップによる表示順変更（キーボードおよび上下ボタンにも対応）
- 新規商品を管理一覧・会計画面の先頭へ追加
- 「売り切れ」と「非表示」を別々に管理
- 売り切れ商品を会計画面に表示したまま追加操作を無効化
- 現金受取額、お釣り、会計履歴
- 会計履歴の日別集計と商品別販売数
- JSONバックアップの共有・ダウンロード、置換または追加による復元
- オフライン動作、ホーム画面アイコン、操作効果音

## 開発

必要環境はNode.js 22以降とnpmです。

```bash
npm install
npm run dev
```

同じLANのiPhoneから確認する場合は `npm run dev -- --host` を使います。Service Workerとホーム画面追加の実機確認にはHTTPS環境を推奨します。

## テストとビルド

```bash
npm run format:check
npm run lint
npm run test
npm run build
npm run test:e2e
```

PlaywrightのWebKitが未導入の場合は、初回だけ `npx playwright install webkit` を実行してください。

## iPhoneへのインストール

1. HTTPSで公開したURLをiPhoneのSafariで開く
2. 共有ボタンをタップ
3. 「ホーム画面に追加」を選ぶ
4. 「バンド物販レジ」のアイコンから起動する

更新が検出された場合は画面上部の更新案内から反映できます。古いアイコンが残る場合は、既存のホーム画面アイコンを削除してから追加し直してください。

正式アイコンの元画像は `public/icons/band-merch-register.png` です。アイコンを差し替えた後もiPhoneのホーム画面に旧アイコンが残る場合は、まず既存のホーム画面アイコンを削除し、Safariからもう一度「ホーム画面に追加」してください。Service Worker更新後も反映されない場合も、Safariのサイトデータを削除する前にこの再追加を試してください。

## 商品の並び替えと売り切れ

「商品」画面の管理一覧で、左端のハンドルをドラッグすると順番を変更できます。操作しづらい場合は各行の上下ボタンも使用できます。保存された順番は会計画面にも反映されます。

新規商品は一覧の先頭へ追加され、既存商品の相対順序は維持されます。登録後は通常どおりドラッグまたは上下ボタンで自由に変更できます。

「売り切れ」は会計画面に商品を残したまま購入操作だけを止めます。「非表示」は会計画面から商品を隠します。売り切れに変更された商品がカートに入っていた場合、その数量は安全のため自動的に0へ戻ります。

## 会計履歴

履歴は端末のローカル日付ごとに新しい日から表示されます。当日は最初から開き、過去日は折りたたみます。各日の売上合計、会計件数、販売点数、商品別販売数を確認できます。

## 預かり金

クイック入力は「100円」「500円」「1,000円」「5,000円」「10,000円」「ちょうど」の6種類です。金額ボタンは押すたびに現在の預かり金へ加算され、手入力した値とも合算されます。

「ちょうど」は加算ではなく、預かり金を現在の合計金額へ置き換えます。商品が未選択の場合は使用できません。入力をやり直す場合は、預かり金入力欄右側の消去ボタンを使用してください。商品の選択数量は消去されません。

## バックアップと復元

「商品」画面のデータ管理からバックアップできます。

- iPhone・iPad: 「バックアップ」を押し、共有メニューの「ファイルに保存」を選択
- PCなど共有非対応環境: JSONファイルとして自動ダウンロード
- 復元: 「復元」からJSONを選択し、内容と件数を確認して「置き換え」または「追加」を選択

「置き換え」は現在の商品・履歴・設定をすべて消してバックアップ内容へ置き換えます。「追加」は同じIDのデータだけをバックアップ側の内容で更新します。処理はIndexedDBトランザクション内で行われます。

Safariの履歴・Webサイトデータの削除、iOSによるストレージ整理、公開URL（オリジン）の変更などで端末内データを失う可能性があります。イベント前後にバックアップし、iCloud Drive等の端末外にも保管してください。

旧形式のバックアップに売り切れ設定や効果音設定が含まれない場合は、安全な初期値で補完して復元します。

## デプロイ

`npm run build` で作られる `dist/` を静的ホスティングへ公開します。サブディレクトリ配信ではbase pathを指定します。

```powershell
$env:VITE_BASE_PATH = "/band-merch-register/"
npm.cmd run build
```

### GitHub Pages

公開URL:

https://lushlifelikenightflight-hue.github.io/band-merch-register/

`main`ブランチへpushすると、`.github/workflows/deploy-pages.yml`がNode.js 22で`npm ci`と`npm run build`を実行し、`dist/`をGitHub公式Pages Actionsで自動公開します。Actions画面の「Run workflow」から手動実行もできます。

本番ビルドでは`VITE_BASE_PATH=/band-merch-register/`を指定します。Viteのアセット、Manifest、Service Worker、アイコン、効果音はこのbase pathから配信されます。SPAの直接アクセス用に、workflowが`dist/index.html`と同内容の`dist/404.html`を追加します。ローカル開発ではbase pathを指定しないため、従来どおり`http://localhost:5173/`で動作します。

初回のみ、GitHubリポジトリの「Settings」→「Pages」→「Build and deployment」→「Source」で「GitHub Actions」を選択してください。その後、Actionsの「Deploy to GitHub Pages」が成功し、公開URLから起動・画面遷移・ホーム画面追加・オフライン再起動を確認します。

Netlifyなどへ手動公開する場合は、通常どおり対象URLに合わせて`VITE_BASE_PATH`を設定し、生成された`dist/`を公開できます。GitHub Pagesへ完全移行し、独自ドメイン・Netlify固有の環境変数・リダイレクト・デプロイ履歴が不要になった時点でNetlify版を削除できます。

## 制約

- データは端末・ブラウザ・公開URLごとに独立し、自動同期されません。
- 在庫数、返品、複数税率、レシート、決済サービス連携は対象外です。
